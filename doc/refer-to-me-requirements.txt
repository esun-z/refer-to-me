### Refer to Me 需求快照

设计一个用于监听多渠道消息是否与关注的一个或多个主题相关，并发出对应提醒信息的桌面应用程序。

#### 功能性需求：

- 程序能从某个网络地址来接收外部推送的推送消息作为输入，作为内置的输入连接器；同时还应保持后续可针对不同信息源开发新连接器。
- 用户可在图形用户界面中配置若干个自己可能关心的消息主题，例如“月例会”，“年会旅游报销政策”等（详见消息主题识别流水线设计）。适当设计界面以提示用户配置包含严格匹配字符串和适用于 Laya 执行分类的信息，以提高效果。
- 用户可以从输入框中输入模拟消息，以测试某条消息到来时系统的响应。
- 用户可以为每个监听的主题配置提示方式：无提示、播放提示音、发送 Windows Toast 通知（仅限 Windows）、使用 PySide6 内置机制发送通知（跨平台）、使用指定的 ntfy 发布消息更新。
- 用户可配置对 Laya 模型识别结果的置信度阈值和 OpenAI 兼容的 LLM 接口，以便在 Laya 模型输出置信度过低时路由到 LLM 判断（可选配置，也可以只用 Laya）。
- 用户可配置当消息最终无法分类（例如 LLM 调用失败、未配置 LLM 且 Laya 结果低于阈值）时，发出提示的方式。
- 图形界面应该显示输入、匹配过程和提醒输出日志，并配合简要统计信息，以便用户判断工作情况。
- 对路由到 Laya 模型的请求，记录全部 Laya 推理参数和推理结果到独立数据文件中，以便后续用户决定是否在外部工具中进行人工打标和微调（但本工具仅专注于推理，辅助进行数据集收集）。

#### 消息主题识别流水线

流水线应由简到难，由低成本到高运算量逐级递增。每层都具有短路设计，一旦确认结果就退出识别并输出提醒。

1. 字符串（或正则模板）匹配：如果消息完美匹配了用户预设的一个或多个主题的某个关键词字符串，则立即发出提醒，跳过后续识别。
2. Laya 模型识别：调用 Laya 模型判断消息属于用户配置的哪一类或几类（或不属于任何一类关心的主题）。
3. 若 Laya 模型的置信度低于用户配置要求，调用 LLM 接口（若用户已配置）来进行判断。

#### 技术性需求

- 程序使用 Python 3.12，使用 uv 管理项目依赖和虚拟环境。
- 使用 [Laya](https://github.com/NandhaKishorM/laya) 作为核心判断引擎，默认用户具备 CUDA12.6（uv Pytorch 配置方法详见 https://docs.astral.sh/uv/guides/integration/pytorch ），可回退至 CPU。
- 使用 PySide6 实现图形用户交互界面。
- 使用 windows_toasts 包发送 Windows Toast 通知。
- 如果路由到 LLM，使用 instructor 库确保 LLM 输出被正确结构化。
